💸 Spend habits · 1 of 2

Defaults that save the pool

  • Completions first. They're free — boilerplate, routine code, tests-by-example. Chat is for what completions can't reach.
  • Right-size the model. Cheap tier for everyday questions and mechanical edits; escalate to frontier deliberately, for genuinely hard problems.
  • Think with Gemini, implement with Copilot. Research, comparisons, and brainstorming the approach cost zero credits on Gemini.
⚠️ False economy is real: three failed retries on a cheap model cost more than one clean answer from a mid model. Bring these cases to Friday.
💸 Spend habits · 2 of 2

Discipline per prompt

  • Attach the files that matter, not the workspace. Attached context is billed input, every turn.
  • New chat per task. A bloated thread re-sends its history on every message — caching softens it to ~10%, it never makes it free.
  • One good prompt beats five vague ones. Goal, constraints, relevant files, what "done" looks like. Retries are re-billed in full.
  • Keep the extras off. Higher reasoning and the 1M-token context window multiply burn — switch them on for a reason, then back off.
🤖 The expensive surface

Agent mode is a power tool

  • It bills every token of its autonomous iterations — reading files, retrying, self-correcting. Long sessions cost what they cost.
  • Use it for genuinely multi-file work with clear acceptance criteria stated up front.
  • Watch it. Stop a session that's flailing — a run that isn't converging won't get cheaper.
  • A one-file change is a chat edit or a completion, not an agent run.

🕵️ Personal accounts

They train on you by default

  • ChatGPT and personal Gemini — train on conversations by default (opt-out buried in settings).
  • Copilot Individual — trains on your code by default since April 2026. Our Business seats don't: one more reason to work signed into the org account.
  • Claude — asks at signup instead of assuming.
🚫 Personal accounts are for generic learning only. No client code, no internal data, nothing identifying a client — and if you use one at all, disable training. Spot an AI clause in a client contract? Raise it with the team first.
✅ Quality gates

Same bar as hand-written code

  • You own what you ship. Never commit a line you can't explain — "Copilot wrote it" is not a review response.
  • Same PR review as everything else. Note large generated chunks in the description so the reviewer knows where to slow down.
  • Non-trivial generated logic gets a test. Plausible-but-wrong is the signature AI failure mode.
  • Extra scrutiny on sensitive paths: auth, permissions, input validation, payments, crypto.
  • Hygiene unchanged: Conventional Commits, and PR text that describes the actual diff.
🗂️ Repo standard

Every repo gets an AGENTS.md

  • One canonical, tool-agnostic guide at the root — dev commands, conventions, repo map, gotchas. Camomilla's is the reference example.
  • Wire VS Code to read it: commit "chat.useAgentsMdFile": true in .vscode/settings.json.
  • .github/copilot-instructions.md stays a thin pointer — 3 lines + "see AGENTS.md".
  • Keep instruction files lean: they ride along on every request — a bloated file is a tax on every prompt, org-wide.
⚠️ Gotcha: Copilot has no @file import — that's Claude Code syntax. An @AGENTS.md line in copilot-instructions.md is read as plain text.
📅 Governance

The Friday review decides

  • Which models are enabled — a team decision made in the settings panel, never hard-coded in a doc.
  • Pool pace — credits consumed vs. day of month; if we're heading for the hard block, we agree on what to throttle.
  • What worked at what price — patterns worth copying, workflows that burn credits for nothing, false-economy cases.
  • The price snapshot — updated whenever GitHub changes models or prices.
